2. Agent Div Experiment (AI Agent Behavior)

Before changing to div: The AI Agent could find and click the save button correctly because it used the <button> tag with a clear accessible name.

After changing the button to div: When the save button was changed to a plain <div> tag without role="button" or tabindex, it caused the AI Agent to fail in recognizing or interacting with the button, and the screen reader skipped reading it entirely, leading to failure in completing the main task.

3. Manual Testing Findings (Findings from Manual Testing)

  • 200% Zoom: It was found that in Project A, some parts of the form overlap when the page is zoomed in, but in Project B, the responsive layout passes the Reflow criterion.
  • Screen Reader: The announcement of result counts through aria-live="polite" helps visually impaired users know about changes immediately after typing a search query, which some automated tools do not cover as comprehensively as real-time audio feedback.

4. Key Skill Rules That Make a Difference

The most impactful rules are Focus Management & Keyboard Navigation and the requirement to use Native HTML Elements (do not use div for buttons) which ensures AI generates correct code from the start, preventing errors in focus control within Dialogs.

5. Things AI Got Wrong in the Early Stages

In the early stages, AI often preferred to use generic tags like <div> or <span> with click events instead of using the actual <button> tag, and would often forget to set up scripts to return focus to the original button after closing a Dialog if no custom skills were in place.
