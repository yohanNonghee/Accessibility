Accessibility Evaluation Report

Comparison of two movie directory implementations, including automated accessibility checks, an agent interaction experiment, and manual observations.

1. A/B test comparison

The table summarizes the reported Playwright evaluation of Project A and Project B.

Reported accessibility test outcomes
Test area Project A (without skill) Project B (with skill)
Keyboard navigation and main task Failed: focus was lost and Tab did not reach some controls. Passed: the main task was completed using the keyboard.
Dialog focus management Failed: focus did not move into the dialog or return to its opener. Passed: focus moved into the dialog and returned to the opener.
Accessible names Failed: the save control did not have a clear accessible name. Passed: controls have descriptive accessible names.
Serious or critical Axe violations Four violations were reported. No serious or critical violations were reported in the current scan.

2. Agent interaction experiment

Using a native button: The agent could locate and activate the save control when it was implemented as a <button> with a descriptive accessible name.

Replacing it with a plain div: Without button semantics, keyboard focus, or an accessible role, the agent could not reliably recognize or activate the control, and assistive technology could skip it.

3. Manual testing observations

  • 200% zoom: Some Project A form content overlapped. Project B's responsive layout was observed to reflow more effectively.
  • Screen readers: A polite live region announces result-count changes as the search query changes, providing timely feedback beyond what automated checks alone can verify.

4. Accessibility practices that mattered

Focus management, keyboard support, and native HTML controls were the most consequential practices. Native buttons provide keyboard behavior and accessibility semantics by default; dialogs also need deliberate focus placement and restoration.

5. Common early implementation mistakes

Early drafts sometimes used generic <div> or <span> elements as clickable controls instead of native buttons. They could also omit returning focus to the original control after a dialog closes.
